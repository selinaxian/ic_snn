# NeuCube 风格储备池：输入敏感性与完整响应增量诊断

已完成。复用三个历史折的冻结模型和发放记录，未更改编码、216 神经元参数、5 分钟读出窗口或原日期划分，没有再训练储备池。此项目是 NeuCube 风格的轻量实现，不等同于完整官方软件。

结论：当前 STDP 池在输入时点扰动下较随机池更少变化；完整响应没有改善下一分钟绝对收益的预测，第三轮误差反而增大。结合已有停输入仍持续发放的证据，应关注内部循环对响应的主导，而不能把大量复现模式直接解释为有用的金融学习。

## 固定口径

三轮分别在第 1–81/101/121 天训练 STDP，接下来 20 天只拟合读出，再冻结测试 20 天。测试日期分别为 2026-06-09—07-07、07-08—08-06、08-07—09-08。全部属于已使用历史数据，不是新独立研究验证。

目标为 `abs(log(close[t+1]/close[t]))*10000`，下一分钟收盘到收盘绝对对数收益，单位 bp，无方向。午休、隔夜与缺口不跨段，每段末尾可出分但没有标签。

原始因子用最近五个时点的六个既有特征，30 维；响应保留 5×216=1080 个完整位置。原始因子组、原始因子＋随机池组、原始因子＋STDP 池组使用相同预测点与线性读出。仅用校准期标准化：每列去均值除标准差，特征块再除有效维数平方根。目标函数为平均平方误差加 0.01 倍系数平方和，固定惩罚，不选型，预测截为非负。

每轮 4,600 个逐分钟输出，其中 4,560 个有标签，共 13,800 行/13,680 个有标签分钟。每轮四十个时段末端只保留预测，不补未来标签。原始金融权重、输入映射、已保存发放记录均未修改。

## 输入扰动结果

每个测试连续时段固定两个位置，共每轮 80 个背景。重放完全相同的前史，然后反转最后五个已编码分钟块；另一个对照只将通道 0 循环移动一分钟。保持每通道总脉冲数不变，不改变其他输入。标签不参与扰动或位置选择。以下为改变前后完整响应的平均 Jaccard：

| 扰动 | 网络 | 第一轮 | 第二轮 | 第三轮 |
|---|---|---:|---:|---:|
| 反转五分钟 | 随机池 | 81.03% | 81.80% | 83.18% |
| 反转五分钟 | STDP 池 | 96.77% | 96.86% | 97.16% |
| 移动通道 0 | 随机池 | 95.65% | 95.43% | 96.16% |
| 移动通道 0 | STDP 池 | 99.50% | 99.38% | 99.61% |

STDP 池平均约 30.6% 的神经元每分钟发放，随机池约 20.8%–21.0%。高密度本身会抬高 Jaccard，但原始 Hamming 差异也更小：反转时 STDP 只有约 0.89%–1.01% 的格子改变，随机池为 3.96%–4.50%。最后一分钟差异也是 STDP 更小（约 1.61%–1.63%，随机约 8.62%–9.98%）。因此不只是 Jaccard 分母造成的现象。

不能将“更不敏感”单独判断为坏事，它也可能表示稳定性；更敏感也可能是噪声。当前结合三步循环与停输入审计、以及下面的预测结果，只能说没有证据表明这种不变性保留了对所选目标更有用的信息。单通道测试只覆盖预先指定的通道 0，不能外推为所有因子均不起作用。

## 限制与可用输出

这轮只检验固定线性读出对下一分钟绝对收益的可用信息，不能证明完整响应对所有市场状态或非线性读出都无用。读出使用校准期拟合，没有遍历正则化强度；单个固定惩罚也不是证明所有读出失败。原始因子基线仅含原五分钟历史，未穷举原始行情模型。这个任务是定位当前瓶颈，不是寻找最优预测器。

`minute_signals.csv` 的 `pred_stdp` 是可复算的下一分钟绝对收益估计（bp），可拿来分析，但目前不能称为优于原始因子的 STDP 信号。请同时保留 `pred_raw` 与 `pred_random`。`actual_abs_1m_bp` 是事后标签，不能参与实盘信号。没有交易、交易成本或可执行入场假设。

## 文件与复算

在 snn_project 目录运行 `python scripts/response_value_audit.py`，要求输出目录不存在，防止覆盖。`python scripts/verify_response_audit.py` 从原冻结记录与保存读出重建预测和标签。

结果文件包括协议、逐分钟预测、误差、按日区间、逐场景扰动与汇总、各折读出标准化参数和系数、完成与复算核验记录。冻结模型回放与原 trace 逐元素相同，各扰动保持通道计数，仿真期间权重不变。源文件哈希保存在 verification.json。

本项目与 00snn 的行情、因子、窗口、日期都不同，不能根据两份 RMSE 判断架构优劣。
